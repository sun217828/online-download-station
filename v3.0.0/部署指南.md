第一部分：你需要提前准备的东西
================================================================

1. 一台安装了 Ubuntu 22.04 LTS 的服务器（物理机或云服务器均可）
2. 服务器有公网 IP（如果要外网访问）或内网 IP（仅内网使用）
3. 服务器上有 sudo / root 权限
4. 服务器上行带宽越大越好（决定下载速度）

【重要提醒】以下所有软件均需安装，别漏！


================================================================
第二部分：一步一步安装命令（按顺序执行）
================================================================

-------- 步骤 1：更新系统软件源 --------
sudo apt update
sudo apt upgrade -y


-------- 步骤 2：安装 Node.js 和 npm --------
# Ubuntu 22.04 自带的 Node 版本较旧，使用 NodeSource 安装新版
# 这里安装 Node.js 20.x LTS（v3.0 要求 Node ≥ 16，建议 20）

curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# 验证安装（显示 v20.x.x 即成功）
node -v
npm -v


-------- 步骤 3：安装编译工具 --------
# v3.0 用到了 better-sqlite3（数据库），它需要在安装时本地编译
# 所以必须装编译工具，否则 npm install 会失败

sudo apt install -y build-essential python3


-------- 步骤 4：创建项目目录 --------
# 你可以选择任意目录，这里放到 /opt 下（推荐）
sudo mkdir -p /opt/file-download-server
sudo chown -R $USER:$USER /opt/file-download-server
cd /opt/file-download-server


-------- 步骤 5：上传项目文件 --------
# 方法 A：用 scp 从本地电脑上传（在你自己电脑上执行）
# scp -r /本地路径/文件下载站v3.0/* 你的用户名@服务器IP:/opt/file-download-server/

# 方法 B：用 WinSCP / FileZilla 等图形化 SFTP 工具上传
# 把 package.json, server.js, db.js, public/ 这几个文件传上去即可

# 方法 C：如果文件已经在服务器上，直接 cp 过来


-------- 步骤 6：安装项目依赖 --------
cd /opt/file-download-server
npm install

# 等待安装完成，最后会显示 "added X packages" 等字样
# 如果国内服务器 npm 慢，可以换淘宝镜像再装：
# npm config set registry https://registry.npmmirror.com
# npm install

# 注意：better-sqlite3 会编译几秒钟到一两分钟，是正常现象，请耐心等待
# 如果报错 EACCES（缓存目录权限问题），执行：
#   sudo chown -R $(id -u):$(id -g) ~/.npm
# 然后重新 npm install


-------- 步骤 7：创建文件存放目录并放入安装包 --------
# 在项目目录下创建 files 文件夹（首次启动也会自动创建，这里手动建一次保险）
mkdir -p /opt/file-download-server/files

# 【重要】把你要分享的安装包复制到这个目录下！
# 例如：
# cp /你的大文件路径/SolidWorks_2022.exe /opt/file-download-server/files/

# 推荐文件名格式：中文名_版本号.扩展名
# 如：SolidWorks_2022.exe  /  AutoCAD_2023.iso  /  Office_2021.zip
# 这样页面上会自动解析出软件名和版本号


-------- 步骤 8：测试启动服务 --------
cd /opt/file-download-server
node server.js

# 正常启动后会显示类似：
# ========================================
#    文件下载站 已启动
# ========================================
#   监听地址  : http://0.0.0.0:8080
#   下载目录  : /opt/file-download-server/files
#   私密目录  : /opt/file-download-server/files-private
#   待审目录  : /opt/file-download-server/pending
#   访问地址  : http://你的服务器IP:8080

# 然后用浏览器访问 http://服务器IP:8080 看能不能打开页面
# 看到页面后，按 Ctrl+C 停止服务，继续下一步开机自启配置


================================================================
第三部分：网口（公网访问配置）
================================================================

（此部分内容较为复杂，且公网 ICP 备案周期较长，建议先在内网跑通后再处理。
 以下两种方案保留备用，按需选择。）

两种选择，取决于你家宽带有没有公网IP：

  方案A：有公网IP → 路由器做端口映射
         → 同事直接访问：http://你的公网IP:8080
         → 最简单、最干净、最推荐

  方案B：没公网IP → 用 Tailscale Funnel（只有你家装，同事不用装）
         → 同事访问：https://xxx.tailnet-dc.ts.net（一个公开网址）
         → 同事零安装、零配置，纯浏览器打开

两种方案各有优劣，先查你家有没有公网IP，再选方案。


第一步：先查有没有公网IP

在你家服务器的终端里执行：

  curl ifconfig.me
  # 会输出一串数字，比如 123.45.67.89，记下来

然后再查路由器里看到的 WAN 口IP：
  方法：浏览器打开你家路由器管理页面（通常是 192.168.1.1 或 192.168.0.1）
        找到「网络状态」或「WAN口信息」，看 WAN IP 是多少

对比两个IP：
  ★ 如果一样 → 你有公网IP！→ 直接用【方案A】
  ★ 如果不一样 → 你没有公网IP → 只能用【方案B】


---------------A：有公网IP → 路由器做端口映射

【原理】
把你家路由器的 8080 端口，转发到服务器内网IP的 8080 端口上。
这样外网访问 公网IP:8080 → 自动转到服务器 → 打开下载站。

---

A-1：先查服务器的内网IP

终端执行：
  hostname -I
  # 输出第一个就是内网IP，比如 192.168.1.100
  ★ 记下来，下一步要用

---

A-2：给服务器设置固定内网IP（重要！不然重启可能变）

两种方法任选：

方法一：路由器里绑定（推荐）
  浏览器打开路由器管理页（192.168.1.1）
  找到「DHCP静态地址分配」或「静态IP绑定」
  找到你服务器的设备名（或MAC地址），绑定固定IP
  比如把 MAC 地址 xxx 绑定到 192.168.1.100
  保存，路由器重启生效

方法二：Ubuntu 系统里设
  桌面右上角 → 网络图标 → 有线设置 → IPv4
  把自动(DHCP)改成手动
  填：
    地址：192.168.1.100（和刚才绑定的一样）
    子网掩码：255.255.255.0
    网关：192.168.1.1（路由器IP）
    DNS：192.168.1.1 或 223.5.5.5
  保存，断开重连

---

A-3：在路由器里做端口映射（端口转发）

浏览器打开路由器管理页：

  找到「虚拟服务器」或「端口映射」或「端口转发」或「NAT转发」
  （不同品牌路由器名字不一样，总之找带「端口」俩字的）

  添加一条规则：
    外部端口（WAN端口）：8080
    内部端口（LAN端口）：8080
    协议：TCP
    内部IP（目标IP）：192.168.1.100（就是你服务器的内网IP）
    状态：启用 / 生效

  保存，路由器重启生效

---

A-4：Ubuntu 防火墙放行 8080

终端执行：
  sudo ufw allow 8080/tcp
  sudo ufw reload
  sudo ufw status
  # 应该看到 8080/tcp 是 ALLOW

---

A-5：验证能不能用

先确认下载站服务在运行：
  cd /opt/file-download-server
  node server.js
  # 或者如果你已经用 systemd 启了就跳过这步

然后测试：
  1. 用手机连 4G/5G（不要连家里WiFi！）
  2. 手机浏览器打开：http://刚才curl查的公网IP:8080
     例：http://123.45.67.89:8080
  3. 能看到页面、能点下载 → 成功！

如果打不开，排查：
  - 路由器端口映射规则有没有写错
  - Ubuntu 防火墙有没有放行 8080
  - 服务有没有在运行（node server.js 或 systemctl status）
  - 有些运营商会封 80/8080 等端口，换个端口试试（比如 8888 或 20000+）

---

A-6：发给同事

把 http://公网IP:8080 发给同事，告诉他用浏览器打开就行。

★ 如果公网IP经常变（家用宽带一般是动态IP），建议用 DDNS
  方法：路由器里找「动态DNS」或「DDNS」，注册免费域名
  （花生壳、TP-LINK DDNS等，大部分路由器自带）
  配好后用域名访问，不怕IP变。


------------------B：没公网IP → Tailscale Funnel（你家装，同事不用装）

【原理】
你家服务器装 Tailscale，开启 Funnel 功能。
Tailscale 会给你一个公开的 https://xxx.ts.net 网址。
任何人用浏览器直接打开这个网址就能访问，不用装任何东西。
而且流量是 P2P 直连，不限速。

---

B-1：安装 Tailscale（服务器上操作）

终端执行：
  curl -fsSL https://tailscale.com/install.sh | sh

---

B-2：登录 Tailscale

终端执行：
  sudo tailscale up

  会弹出一个链接，比如：
    https://login.tailscale.com/a/xxxxxxx
  复制到浏览器打开
  选「Sign in with GitHub」→ 用你的 GitHub 账号登录
  授权成功就好

---

B-3：开启 Funnel 功能（关键！这步让同事零安装）

终端执行（一次性配置）：

  # 1. 先在 Tailscale 网页管理后台开启 Funnel 功能
  #    浏览器打开 https://login.tailscale.com/admin/acls
  #    找到 ACL 文件，在 "nodeAttrs": 里面加上：
  #    "https://tailscale.com/funnel": true,
  #
  #    完整 ACL 示例如下（直接把全部内容替换进去）：
  #
  #    {
  #      "acls": [
  #        { "action": "accept", "src": ["*"], "dst": ["*:*"] },
  #      ],
  #      "nodeAttrs": [
  #        {
  #          "target": ["autogroup:admin"],
  #          "attr": [
  #            "https://tailscale.com/funnel",
  #          ],
  #        },
  #      ],
  #    }
  #
  #    保存（点右下角 Save）

  # 2. 回到服务器终端，设置本地服务转发 + 开启 Funnel
  sudo tailscale serve https / http://127.0.0.1:8080
  sudo tailscale funnel 443 on

---

B-4：查看你的公开网址

终端执行：
  tailscale funnel status

  会输出类似：
    https://你的主机名.你的tailnet-dc.ts.net
  （例：https://ubuntu-abcd1234.tail1234.ts.net）

  ★ 把这个网址记下来！发给同事！

---

B-5：验证能不能用

先确认下载站服务在运行：
  cd /opt/file-download-server
  node server.js （或用 systemd）

然后测试：
  1. 用手机连 4G/5G（不要连家里WiFi！）
  2. 手机浏览器打开刚才那串 https://xxx.ts.net 网址
  3. 能看到页面、能点下载 → 成功！

---

B-6：发给同事

把 https://xxx.ts.net 这个网址发给同事，告诉他用浏览器打开就行。
同事电脑不用装任何软件，任何浏览器都能打开。

---

B-7：Tailscale Funnel 常用命令（记一下）

  # 查看 Funnel 状态
  tailscale serve status
  tailscale funnel status

  # 关闭 Funnel（不想公开时）
  sudo tailscale funnel 443 off

  # 重新开启
  sudo tailscale funnel 443 on


================================================================
第四部分：配置开机自启（使用 systemd，推荐方案）
================================================================

-------- 步骤 1：创建 systemd 服务文件 --------
sudo nano /etc/systemd/system/file-download.service


-------- 步骤 2：把以下内容粘贴进去（注意路径与用户名一致）--------

# ======= 从下一行开始复制 =======
[Unit]
Description=Private File Download Server v3.0
After=network.target

[Service]
Type=simple
User=你的用户名          # <--- 改成你的 Ubuntu 用户名，比如 ubuntu 或 root
WorkingDirectory=/opt/file-download-server
ExecStart=/usr/bin/node /opt/file-download-server/server.js
Restart=always
RestartSec=5

# ====== 环境变量配置区（按需修改）======

# 基础配置
Environment=PORT=8080
Environment=HOST=0.0.0.0
Environment=FILES_DIR=/opt/file-download-server/files

# 管理员审核密码（重要！强烈建议改，默认 admin123 极不安全）
Environment=ADMIN_PASSWORD=admin123

# 联系管理员邮箱（设置页"通用"标签会展示给用户，方便他们有问题时找你）
Environment=ADMIN_EMAIL=你的邮箱@example.com

# 每用户私密空间配额（字节，默认 1GB = 1073741824）
Environment=USER_QUOTA_BYTES=1073741824

# ====== 邮件停机通知（可选，不配也能用，只是不能发邮件）======
# 用自己的邮箱做发件服务器，给所有填了邮箱的用户群发通知
# 以 QQ 邮箱为例：
# Environment=SMTP_HOST=smtp.qq.com
# Environment=SMTP_PORT=465
# Environment=SMTP_SECURE=true
# Environment=SMTP_USER=你的QQ邮箱@qq.com
# Environment=SMTP_PASS=QQ邮箱授权码（不是登录密码！）
# Environment=SMTP_FROM=你的QQ邮箱@qq.com

[Install]
WantedBy=multi-user.target
# ======= 复制到上一行为止 =======

# 保存退出 nano：按 Ctrl+O，回车，再按 Ctrl+X


-------- 步骤 3：加载服务并启动 --------
# 重新加载 systemd 配置
sudo systemctl daemon-reload

# 设置开机自启
sudo systemctl enable file-download

# 启动服务
sudo systemctl start file-download

# 查看运行状态（看到绿色的 active (running) 就成功了）
sudo systemctl status file-download

# 其他常用命令
# sudo systemctl stop file-download       # 停止
# sudo systemctl restart file-download    # 重启（修改 server.js 或环境变量后执行）
# sudo systemctl disable file-download    # 取消开机自启
# sudo journalctl -u file-download -f     # 实时查看日志


================================================================
第五部分：放行防火墙端口
================================================================

Ubuntu 22.04 默认可能开启了 ufw 防火墙，需要放行 8080 端口。

-------- 方案 A：使用 ufw（Ubuntu 默认防火墙）--------
# 查看防火墙状态
sudo ufw status

# 如果是 active（已开启），放行 8080 端口
sudo ufw allow 8080/tcp
sudo ufw reload

# 再次查看确认规则已加入
sudo ufw status numbered


-------- 方案 B：如果你用 iptables --------
sudo iptables -I INPUT -p tcp --dport 8080 -j ACCEPT
sudo netfilter-persistent save


-------- 方案 C：云服务器（阿里云 / 腾讯云 / 华为云等）--------
除了上述系统防火墙，云服务器还有「安全组」/「网络ACL」：
1. 登录云服务商控制台
2. 找到你的服务器实例 → 安全组配置
3. 添加入站规则：
   - 协议类型：TCP
   - 端口范围：8080
   - 授权对象：0.0.0.0/0（允许所有 IP，或仅允许公司公网 IP）
4. 保存，约 1 分钟后生效

================================================================
第七部分：修改管理员审核密码（重要！）
================================================================

默认审核密码是 admin123，非常不安全，强烈建议修改。

【推荐方式：改 systemd 服务的环境变量】
  sudo nano /etc/systemd/system/file-download.service
  找到这一行：
    Environment=ADMIN_PASSWORD=admin123
  改成你自己的密码，比如：
    Environment=ADMIN_PASSWORD=NiMiMaZiShen123!
  保存退出后执行：
    sudo systemctl daemon-reload
    sudo systemctl restart file-download
  这种方式改密码不用改代码，更干净。

建议密码至少 8 位，大小写+数字混合。


================================================================
第八部分：管理员面板怎么用
================================================================

【如何进入管理员面板】

v3.0 的管理员入口是隐藏的，需要按特定方式触发：

1. 用浏览器打开网站首页
2. 在 10 秒内，连续点击页面左上角的网站图标（蓝色圆角方块）7 次
3. 会弹出一个密码框
4. 输入你在 ADMIN_PASSWORD 里设置的管理员密码
5. 进入管理员面板

【管理员面板能做的事】

1. 待审核列表
   - 用户上传的文件会先到这里等管理员审核
   - 可以通过（公开到下载站）或拒绝（删除）
   - 也可以改为私密文件（仅管理员可见）

2. 公告管理
   - 发布/编辑/删除首页右上角信箱里的公告
   - 公告会显示未读小红点提醒用户

3. 用户列表
   - 查看所有注册用户
   - 显示用户名、邮箱（如有）、空间使用进度条、注册时间
   - 用户超 1GB 配额会自动锁死上传通道
   - 管理员可手动解锁某用户的上传通道

4. 文件列表
   - 查看所有私密文件

5. 停机通知（需配置 SMTP 邮件）
   - 群发邮件给所有填了邮箱的用户
   - 用于通知服务器维护、新版本上线等

6. 退出登录
   - 退出管理员模式


================================================================
第九部分：邮件停机通知配置（可选）
================================================================

【什么时候需要配】

当你要停机维护、或发布新版本时，希望自动给所有注册用户发邮件提醒。
如果你不需要这个功能，整段跳过即可，不影响网站其他功能。

【前提条件】

1. 你有一个可用的邮箱（QQ 邮箱、163 邮箱、企业邮箱等）
2. 该邮箱已开启 SMTP 服务并获取了授权码

【QQ 邮箱配置示例】

1. 登录 QQ 邮箱网页版
2. 设置 → 账户 → "POP3/IMAP/SMTP" 服务
3. 开启"IMAP/SMTP 服务"
4. 按提示用手机发短信获取 16 位授权码

然后在 systemd 服务文件里加这些环境变量：

  Environment=SMTP_HOST=smtp.qq.com
  Environment=SMTP_PORT=465
  Environment=SMTP_SECURE=true
  Environment=SMTP_USER=你的QQ邮箱@qq.com
  Environment=SMTP_PASS=刚才获取的16位授权码
  Environment=SMTP_FROM=你的QQ邮箱@qq.com

改完执行：
  sudo systemctl daemon-reload
  sudo systemctl restart file-download

【验证是否配置成功】

1. 进入管理员面板 → 点"停机通知"
2. 如果显示绿色"✓ 邮件服务就绪"，说明配置成功
3. 如果显示黄色"⚠️ SMTP 未配置"，说明环境变量没生效，检查服务文件

【163 邮箱配置示例】

  Environment=SMTP_HOST=smtp.163.com
  Environment=SMTP_PORT=465
  Environment=SMTP_SECURE=true
  Environment=SMTP_USER=你的账号@163.com
  Environment=SMTP_PASS=163邮箱授权码
  Environment=SMTP_FROM=你的账号@163.com

【注意】

- 授权码不是邮箱登录密码，是邮箱设置页单独生成的
- 用户注册时填的邮箱会自动成为收件人
- 邮件用密送（BCC）发送，用户之间看不到彼此的邮箱
- 发件人就是你配置的 SMTP_USER 邮箱

第十一部分：可选优化（按需选择）
================================================================

【可选 1】修改端口号
编辑 systemd 服务文件里的 Environment=PORT=新端口
然后：
  sudo systemctl daemon-reload
  sudo systemctl restart file-download
同时防火墙也要放行新端口：
  sudo ufw allow 新端口/tcp

【可选 2】改用 80 端口（HTTP 默认端口，访问时无需加端口号）
# 1. 修改服务端口为 80
# 2. 1024 以下端口需要特殊权限，两种方式：
#    方式 A：允许 node 绑定低端口
#    sudo setcap 'cap_net_bind_service=+ep' /usr/bin/node
#    方式 B：用 nginx 反代（见下）

【可选 3】使用 Nginx 反向代理 + 自定义域名 + HTTPS
如果有域名想通过 https://download.你的域名.com 访问：
1. 安装 nginx：sudo apt install nginx -y
2. 配置文件：sudo nano /etc/nginx/sites-available/file-download
   配置内容（示例）：
   server {
       listen 80;
       server_name download.你的域名.com;
       client_max_body_size 0;  # 不限制上传大小
       location / {
           proxy_pass http://127.0.0.1:8080;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_request_buffering off;  # 大文件上传不缓存
       }
   }
3. 启用配置：
   sudo ln -s /etc/nginx/sites-available/file-download /etc/nginx/sites-enabled/
   sudo nginx -t
   sudo systemctl reload nginx
4. HTTPS 证书用 Let's Encrypt 免费签发即可

【可选 4】限制访问 IP（只允许公司办公室网络访问）
使用 ufw 只允许指定 IP 访问 8080：
sudo ufw delete allow 8080/tcp
sudo ufw allow from 公司公网IP to any port 8080 proto tcp


================================================================
第十二部分：常见问题排查
================================================================

Q1：浏览器打不开页面？
A：依次检查：
   1. 服务是否运行：sudo systemctl status file-download
   2. 端口是否监听：ss -tlnp | grep 8080
   3. 防火墙是否放行：sudo ufw status
   4. 云服务器安全组是否放行了 8080
   5. 服务器 IP 是否能 ping 通

Q2：页面显示「暂无文件」？
A：检查 files 目录下是否有文件：
   ls -lh /opt/file-download-server/files
   注意：隐藏文件（. 开头的）不会显示

Q3：下载速度很慢？
A：本程序是直链下载无限速，速度瓶颈通常是：
   1. 服务器上行带宽（找服务器运营商）
   2. 下载者的下行带宽
   3. 网络路由拥堵
   程序本身不做任何限速

Q4：文件名乱码？
A：Chrome / Edge / Firefox 新版都已支持中文文件名，
   如果遇到个别老浏览器乱码是浏览器问题，不影响下载的文件本身。

Q5：下载到一半断了，续传不生效？
A：只有主流浏览器（Chrome / Edge / Firefox）支持断点续传，
   另外不要删除浏览器里的下载记录，点「继续」才能续传。

Q6：更新了 files 目录里的文件，网页没刷新？
A：点击网页右上角的 ↻ 刷新按钮即可，或按 F5 刷新页面。
   切回浏览器标签页时也会自动刷新。

Q7：npm install 报错 better-sqlite3 编译失败？
A：确认已安装编译工具：
   sudo apt install -y build-essential python3
   然后删除 node_modules 重装：
   rm -rf node_modules
   npm install

Q8：npm install 报错 EACCES 权限问题？
A：执行：
   sudo chown -R $(id -u):$(id -g) ~/.npm
   然后重新 npm install

Q9：用户注册不了/登录不了？
A：检查数据库目录是否可写：
   ls -la /opt/file-download-server/data/
   应该看到 app.db 文件，且当前用户有写权限。
   如果没有，停掉服务，删除 data 目录后重启：
   sudo systemctl stop file-download
   rm -rf /opt/file-download-server/data
   sudo systemctl start file-download

Q10：邮件停机通知发不出？
A：检查：
   1. systemd 服务文件里 SMTP_* 环境变量是否填了
   2. 改完后是否执行了 daemon-reload + restart
   3. 进入管理员面板"停机通知"看状态提示
   4. 看 journalctl 日志：
      sudo journalctl -u file-download -f
      然后发一封测试邮件，看具体报错

Q11：用户上传后没出现在待审核列表？
A：检查 pending 目录：
   ls -lh /opt/file-download-server/pending/
   如果有文件，刷新管理员面板即可
   如果没文件，可能是上传失败，让用户重新上传

Q12：用户私密空间满了传不上去？
A：用户超 1GB 配额后上传通道会自动锁死。
   管理员可在"用户列表"里手动解锁该用户：
   管理员面板 → 用户列表 → 对应用户行 → 点"解锁"
   解锁后用户可继续上传，但建议用户先删除部分旧文件

第十四部分：数据备份建议

【需要备份的目录】
  /opt/file-download-server/files/         # 公开文件
  /opt/file-download-server/files-private/ # 用户私密文件（含背景图）

【简单备份命令】
  # 打包整个项目目录到 /backup
  sudo mkdir -p /backup
  sudo tar -czf /backup/file-download-$(date +%Y%m%d).tar.gz \
    /opt/file-download-server/files \
    /opt/file-download-server/files-private \
    /opt/file-download-server/data \
    /opt/file-download-server/feedback

【自动每日备份】
  sudo crontab -e
  加一行（每天凌晨 3 点备份）：
  0 3 * * * tar -czf /backup/file-download-$(date +\%Y\%m\%d).tar.gz /opt/file-download-server/files /opt/file-download-server/files-private /opt/file-download-server/data /opt/file-download-server/feedback

【数据库单独备份（更轻量）】
  SQLite 数据库可以直接复制文件备份，不需要停服务：
  cp /opt/file-download-server/data/app.db /backup/app-$(date +%Y%m%d).db
