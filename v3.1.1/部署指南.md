================================================================
        一：需求
================================================================

1. 一台安装了 Ubuntu 22.04 +的服务器（本地服务器或公司服务器均可）
2. 服务器有公网 IP（如果要外网访问）或内网 IP（仅内网使用）
3. 服务器上有 sudo / root 权限
4. 服务器上行带宽越大越好（决定下载速度）

【重要提醒】以下所有软件均需安装，别漏！

================================================================
第三部分：网络访问配置（已有域名 / 公司内网 二选一）
================================================================

本部分不再使用公网穿透（Tailscale Funnel 等），改为两种常规方案，
按你的实际网络环境二选一即可：

  方案 A：使用已有域名 + Nginx 反向代理（推荐，支持 HTTPS）
          → 同事访问：https://download.你的域名.com
          → 适合公司有自有域名、有公网服务器或已做内网穿透到公网的场景

  方案 B：公司内网直连（最简单，零额外组件）
          → 同事访问：http://服务器内网IP:8080
          → 适合纯内网办公环境，服务器和同事在同一局域网

先查服务器内网 IP（两种方案都要用）：
  hostname -I
  # 输出第一个就是内网 IP，比如 192.168.1.100，记下来


---------------A：使用已有域名 + Nginx 反向代理（推荐）

【适用场景】
你已有一个域名（如 download.yourcompany.com），并能修改其 DNS 解析。
服务器可以是公司有公网 IP 的服务器，也可以是纯内网服务器（通过公司公网入口反代）。

---

A-1：配置域名 DNS 解析

登录你的域名服务商后台：
  1. 添加一条 A 记录：
     主机记录：download（或你想要的子域名前缀）
     记录类型：A
     记录值：你的服务器公网 IP 或公司出口公网 IP
     TTL：默认 10 分钟即可
  2. 保存，等待解析生效（通常 1-10 分钟）
  3. 验证：在任意电脑执行
     ping download.yourcompany.com
     能解析到你的 IP 就 OK

【如果服务器在纯内网】
  需要让公司公网入口（路由器/防火墙）把 80/443 端口转发到内网服务器，
  或在公司已有的反向代理（Nginx/网关）上加一条转发规则指向内网服务器 8080。

---

A-2：给服务器设置固定内网 IP（重要！）

  方法一：路由器/ DHCP 里绑定（推荐）
    在公司路由器或 DHCP 服务器里，把服务器 MAC 绑定到固定 IP

  方法二：Ubuntu 系统里设静态 IP
    桌面右上角 → 网络 → 有线设置 → IPv4 → 改成手动
    地址：192.168.1.100（与现状一致）
    子网掩码：255.255.255.0
    网关：192.168.1.1
    DNS：223.5.5.5 或公司 DNS

---

A-3：安装 Nginx

  sudo apt install -y nginx

---

A-4：配置 Nginx 反向代理

  sudo nano /etc/nginx/sites-available/file-download

粘贴以下内容（按需修改 server_name）：

  server {
      listen 80;
      server_name download.yourcompany.com;   # ← 改成你的域名

      # 大文件上传不缓存，支持分片上传
      client_max_body_size 0;
      proxy_request_buffering off;
      proxy_read_timeout 3600s;
      proxy_send_timeout 3600s;

      location / {
          proxy_pass http://127.0.0.1:8080;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
          # 分片上传要支持长连接
          proxy_http_version 1.1;
      }
  }

启用配置并重载：
  sudo ln -sf /etc/nginx/sites-available/file-download /etc/nginx/sites-enabled/
  sudo rm -f /etc/nginx/sites-enabled/default
  sudo nginx -t
  sudo systemctl reload nginx

---

A-5：申请 HTTPS 证书（Let's Encrypt 免费证书，强烈推荐）

  sudo apt install -y certbot python3-certbot-nginx
  sudo certbot --nginx -d download.yourcompany.com
  # 按提示输入邮箱、同意条款，选择自动把 HTTP 跳转 HTTPS
  # certbot 会自动改好 Nginx 配置并设置自动续期

验证：浏览器打开 https://download.yourcompany.com 应该能看到页面。
证书每 90 天自动续期，无需手动操作。

---

A-6：防火墙放行

  sudo ufw allow 80/tcp
  sudo ufw allow 443/tcp
  sudo ufw allow 8080/tcp   # 内网直连调试用，外网可不开
  sudo ufw reload

若服务器前有公司防火墙/网关，还要在对应设备上放行 80/443 入站。

---

A-7：把网址发给同事

  https://download.yourcompany.com
  告诉同事用浏览器打开即可，无需安装任何软件。


------------------B：公司内网直连（最简单）

【适用场景】
服务器和所有同事在同一公司局域网内，不需要外网访问。
无需域名、无需 Nginx、无需证书，开箱即用。

---

B-1：给服务器设置固定内网 IP（重要！不然重启会变）

参考 A-2，把服务器 IP 固定为 192.168.1.100（示例）。

---

B-2：Ubuntu 防火墙放行 8080

  sudo ufw allow 8080/tcp
  sudo ufw reload
  sudo ufw status
  # 应看到 8080/tcp ALLOW

---

B-3：启动服务

  cd /opt/file-download-server
  node server.js
  # 或已配置 systemd 则：sudo systemctl start file-download

---

B-4：验证

  1. 在同事电脑浏览器打开：http://192.168.1.100:8080
     （把 192.168.1.100 换成你服务器实际 IP）
  2. 能看到页面、能点下载 → 成功！

---

B-5：把网址发给同事

  http://192.168.1.100:8080
  同事用浏览器打开即可。

【可选】在内网 DNS 服务器加一条解析：
  download.intranet → 192.168.1.100
  之后同事就能用 http://download.intranet:8080 访问，更好记。


================================================================
第四部分：配置开机自启（使用 systemd，推荐方案）
================================================================

-------- 步骤 1：创建 systemd 服务文件 --------
sudo nano /etc/systemd/system/file-download.service


-------- 步骤 2：把以下内容粘贴进去（注意路径与用户名一致）--------

# ======= 从下一行开始复制 =======
[Unit]
Description=Private File Download Server v3.0
After=network.target

[Service]
Type=simple
User=你的用户名          # <--- 改成你的 Ubuntu 用户名，比如 ubuntu 或 root
WorkingDirectory=/opt/file-download-server
ExecStart=/usr/bin/node /opt/file-download-server/server.js
Restart=always
RestartSec=5

# ====== 环境变量配置区（按需修改）======

# 基础配置
Environment=PORT=8080
Environment=HOST=0.0.0.0
Environment=FILES_DIR=/opt/file-download-server/files

# 审核后台口令（已废弃，审核改用管理员登录密码验证，此项仅兼容保留）
Environment=ADMIN_PASSWORD=admin123

# 联系管理员邮箱（设置页"通用"标签会展示给用户，方便他们有问题时找你）
Environment=ADMIN_EMAIL=你的邮箱@example.com

# 每用户私密空间配额（字节，默认 10GB = 10737418240）
Environment=USER_QUOTA_BYTES=10737418240

# ====== 邮件停机通知（可选，不配也能用，只是不能发邮件）======
# 用自己的邮箱做发件服务器，给所有填了邮箱的用户群发通知
# 以 QQ 邮箱为例：
# Environment=SMTP_HOST=smtp.qq.com
# Environment=SMTP_PORT=465
# Environment=SMTP_SECURE=true
# Environment=SMTP_USER=你的QQ邮箱@qq.com
# Environment=SMTP_PASS=QQ邮箱授权码（不是登录密码！）
# Environment=SMTP_FROM=你的QQ邮箱@qq.com

# ====== 分片上传（第 4 期新增，一般不用动，保持默认即可）======
# 分片暂存目录（上传中的文件碎片存这里，合并完会自动清理）
# Environment=CHUNK_UPLOAD_DIR=/opt/file-download-server/chunks
# 默认分片大小（字节，默认 5MB=5242880，范围 64KB~10MB）
# 5MB 适合大多数场景：弱网重试成本低，并发数够用
# Environment=CHUNK_SIZE_BYTES=5242880

[Install]
WantedBy=multi-user.target
# ======= 复制到上一行为止 =======

# 保存退出 nano：按 Ctrl+O，回车，再按 Ctrl+X


-------- 步骤 3：加载服务并启动 --------
# 重新加载 systemd 配置
sudo systemctl daemon-reload

# 设置开机自启
sudo systemctl enable file-download

# 启动服务
sudo systemctl start file-download

# 查看运行状态（看到绿色的 active (running) 就成功了）
sudo systemctl status file-download

# 其他常用命令
# sudo systemctl stop file-download       # 停止
# sudo systemctl restart file-download    # 重启（修改 server.js 或环境变量后执行）
# sudo systemctl disable file-download    # 取消开机自启
# sudo journalctl -u file-download -f     # 实时查看日志


================================================================
第五部分：放行防火墙端口
================================================================

Ubuntu 22.04 默认可能开启了 ufw 防火墙，需要放行 8080 端口。

-------- 方案 A：使用 ufw（Ubuntu 默认防火墙）--------
# 查看防火墙状态
sudo ufw status

# 如果是 active（已开启），放行 8080 端口
sudo ufw allow 8080/tcp
sudo ufw reload

# 再次查看确认规则已加入
sudo ufw status numbered


-------- 方案 B：如果你用 iptables --------
sudo iptables -I INPUT -p tcp --dport 8080 -j ACCEPT
sudo netfilter-persistent save


-------- 方案 C：公司有硬件防火墙/网关设备 --------
除了上述系统防火墙，公司网络若部署了独立防火墙/网关：
1. 登录防火墙/网关管理后台
2. 添加入站规则：
   - 协议类型：TCP
   - 端口范围：8080
   - 授权对象：0.0.0.0/0（允许所有 IP，或仅允许公司公网 IP / 内网网段）
3. 保存，约 1 分钟后生效

================================================================
第七部分：修改 root 默认密码（重要！）
================================================================

系统首次启动会自动创建 root 超级管理员账号：
  用户名：root
  初始密码：root123

这个密码非常不安全，强烈建议第一时间修改！

【修改方式：登录后在网页里改】
1. 用 root / root123 登录网站
2. 点右上角齿轮 → 用户 → 账号设置 → 修改密码
3. 输入旧密码 root123 和你的新密码，保存

建议密码至少 8 位，大小写+数字混合。

【关于 ADMIN_PASSWORD 环境变量】
v3.0 的审核后台已改为「登录 + 管理员自己的用户密码」验证，
不再使用全局 ADMIN_PASSWORD 口令。
  - root 账号：7 击 Logo 后直接进入，无需密码
  - admin 账号：7 击 Logo 后输入自己的用户登录密码
ADMIN_PASSWORD 环境变量仅作兼容保留，可留默认值不影响安全。
启动日志里仍会打印它，仅作历史兼容提示。


================================================================
第八部分：管理员面板怎么用
================================================================

【如何进入管理员面板】

v3.0 的管理员入口是隐藏的，需要按特定方式触发：

1. 用浏览器打开网站首页
2. 先用 root 或 admin 账号登录（必须先登录！）
3. 在 10 秒内，连续点击页面左上角的网站图标（蓝色圆角方块）7 次
4. 权限分层：
   - root：直接进入管理员面板，无需密码
   - admin：弹出密码框，输入「自己的用户登录密码」验证后进入
   - 普通用户 / 未登录：拒绝进入

【管理员面板能做的事】

1. 待审核列表
   - 用户上传的文件会先到这里等管理员审核
   - 可以通过（公开到下载站）或拒绝（删除）
   - 也可以改为私密文件（仅管理员可见）

2. 公告管理
   - 发布/编辑/删除首页右上角信箱里的公告
   - 公告会显示未读小红点提醒用户

3. 用户列表
   - 查看所有注册用户
   - 显示用户名、邮箱（如有）、空间使用进度条、注册时间
   - 用户超 10GB 配额会自动锁死上传通道
   - 管理员可手动解锁某用户的上传通道

4. 文件列表
   - 查看所有私密文件

5. 停机通知（需配置 SMTP 邮件）
   - 群发邮件给所有填了邮箱的用户
   - 用于通知服务器维护、新版本上线等

6. 退出登录
   - 退出管理员模式


================================================================
第九部分：邮件停机通知配置（可选）
================================================================

【什么时候需要配】

当你要停机维护、或发布新版本时，希望自动给所有注册用户发邮件提醒。
如果你不需要这个功能，整段跳过即可，不影响网站其他功能。

【前提条件】

1. 你有一个可用的邮箱（QQ 邮箱、163 邮箱、企业邮箱等）
2. 该邮箱已开启 SMTP 服务并获取了授权码

【QQ 邮箱配置示例】

1. 登录 QQ 邮箱网页版
2. 设置 → 账户 → "POP3/IMAP/SMTP" 服务
3. 开启"IMAP/SMTP 服务"
4. 按提示用手机发短信获取 16 位授权码

然后在 systemd 服务文件里加这些环境变量：

  Environment=SMTP_HOST=smtp.qq.com
  Environment=SMTP_PORT=465
  Environment=SMTP_SECURE=true
  Environment=SMTP_USER=你的QQ邮箱@qq.com
  Environment=SMTP_PASS=刚才获取的16位授权码
  Environment=SMTP_FROM=你的QQ邮箱@qq.com

改完执行：
  sudo systemctl daemon-reload
  sudo systemctl restart file-download

【验证是否配置成功】

1. 进入管理员面板 → 点"停机通知"
2. 如果显示绿色"✓ 邮件服务就绪"，说明配置成功
3. 如果显示黄色"⚠️ SMTP 未配置"，说明环境变量没生效，检查服务文件

【163 邮箱配置示例】

  Environment=SMTP_HOST=smtp.163.com
  Environment=SMTP_PORT=465
  Environment=SMTP_SECURE=true
  Environment=SMTP_USER=你的账号@163.com
  Environment=SMTP_PASS=163邮箱授权码
  Environment=SMTP_FROM=你的账号@163.com

【注意】

- 授权码不是邮箱登录密码，是邮箱设置页单独生成的
- 用户注册时填的邮箱会自动成为收件人
- 邮件用密送（BCC）发送，用户之间看不到彼此的邮箱
- 发件人就是你配置的 SMTP_USER 邮箱

第十部分：用户使用说明（给网站用户看）
================================================================

【注册与登录】

1. 点击右上角齿轮图标 → "用户"标签

第十一部分：可选优化（按需选择）
================================================================

【可选 1】修改端口号
编辑 systemd 服务文件里的 Environment=PORT=新端口
然后：
  sudo systemctl daemon-reload
  sudo systemctl restart file-download
同时防火墙也要放行新端口：
  sudo ufw allow 新端口/tcp

【可选 2】改用 80 端口（HTTP 默认端口，访问时无需加端口号）
# 1. 修改服务端口为 80
# 2. 1024 以下端口需要特殊权限，两种方式：
#    方式 A：允许 node 绑定低端口
#    sudo setcap 'cap_net_bind_service=+ep' /usr/bin/node
#    方式 B：用 nginx 反代（见下）

【可选 3】使用 Nginx 反向代理 + 自定义域名 + HTTPS
如果有域名想通过 https://download.你的域名.com 访问：
1. 安装 nginx：sudo apt install nginx -y
2. 配置文件：sudo nano /etc/nginx/sites-available/file-download
   配置内容（示例）：
   server {
       listen 80;
       server_name download.你的域名.com;
       client_max_body_size 0;  # 不限制上传大小
       location / {
           proxy_pass http://127.0.0.1:8080;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_request_buffering off;  # 大文件上传不缓存
       }
   }
3. 启用配置：
   sudo ln -s /etc/nginx/sites-available/file-download /etc/nginx/sites-enabled/
   sudo nginx -t
   sudo systemctl reload nginx
4. HTTPS 证书用 Let's Encrypt 免费签发即可

【可选 4】限制访问 IP（只允许公司办公室网络访问）
使用 ufw 只允许指定 IP 访问 8080：
sudo ufw delete allow 8080/tcp
sudo ufw allow from 公司公网IP to any port 8080 proto tcp

第十二部分：常见问题排查
================================================================

Q1：浏览器打不开页面？
A：依次检查：
   1. 服务是否运行：sudo systemctl status file-download
   2. 端口是否监听：ss -tlnp | grep 8080
   3. 防火墙是否放行：sudo ufw status
   4. 公司防火墙/网关是否放行了 8080
   5. 服务器 IP 是否能 ping 通

Q2：页面显示「暂无文件」？
A：检查 files 目录下是否有文件：
   ls -lh /opt/file-download-server/files
   注意：隐藏文件（. 开头的）不会显示

Q3：下载速度很慢？
A：本程序是直链下载无限速，速度瓶颈通常是：
   1. 服务器上行带宽（找服务器运营商）
   2. 下载者的下行带宽
   3. 网络路由拥堵
   程序本身不做任何限速

Q4：文件名乱码？
A：Chrome / Edge / Firefox 新版都已支持中文文件名，
   如果遇到个别老浏览器乱码是浏览器问题，不影响下载的文件本身。

Q5：下载到一半断了，续传不生效？
A：只有主流浏览器（Chrome / Edge / Firefox）支持断点续传，
   另外不要删除浏览器里的下载记录，点「继续」才能续传。

Q6：更新了 files 目录里的文件，网页没刷新？
A：点击网页右上角的 ↻ 刷新按钮即可，或按 F5 刷新页面。
   切回浏览器标签页时也会自动刷新。

Q7：npm install 报错 better-sqlite3 编译失败？
A：确认已安装编译工具：
   sudo apt install -y build-essential python3
   然后删除 node_modules 重装：
   rm -rf node_modules
   npm install

Q8：npm install 报错 EACCES 权限问题？
A：执行：
   sudo chown -R $(id -u):$(id -g) ~/.npm
   然后重新 npm install

Q9：用户注册不了/登录不了？
A：检查数据库目录是否可写：
   ls -la /opt/file-download-server/data/
   应该看到 app.db 文件，且当前用户有写权限。
   如果没有，停掉服务，删除 data 目录后重启：
   sudo systemctl stop file-download
   rm -rf /opt/file-download-server/data
   sudo systemctl start file-download

Q10：邮件停机通知发不出？
A：检查：
   1. systemd 服务文件里 SMTP_* 环境变量是否填了
   2. 改完后是否执行了 daemon-reload + restart
   3. 进入管理员面板"停机通知"看状态提示
   4. 看 journalctl 日志：
      sudo journalctl -u file-download -f
      然后发一封测试邮件，看具体报错

Q11：用户上传后没出现在待审核列表？
A：检查 pending 目录：
   ls -lh /opt/file-download-server/pending/
   如果有文件，刷新管理员面板即可
   如果没文件，可能是上传失败，让用户重新上传

Q12：用户私密空间满了传不上去？
A：用户超 10GB 配额后上传通道会自动锁死。
   管理员可在"用户列表"里手动解锁该用户：
   管理员面板 → 用户列表 → 对应用户行 → 点"解锁"
   解锁后用户可继续上传，但建议用户先删除部分旧文件

================================================================
第十二部分：分片上传相关说明（第 4 期新增）
================================================================

【什么是分片上传？为什么用它？】
  旧版上传是一次性把整个文件塞给服务器，超过 100MB 就容易超时失败。
  第 4 期改成"分片上传"：
    前端把大文件切成 5MB 一片，4 路并发上传，单片失败自动重试 3 次，
    全部传完后服务器流式合并。中途断网可断点续传，已存在的文件可秒传。

【会占多少额外磁盘？】
  上传期间会在 chunks/ 目录暂存分片，总大小 = 文件大小。
  合并成功后会自动清理。24 小时未完成的会话每小时自动清理一次。
  所以最坏情况磁盘占用 ≈ 同时上传的所有文件总大小 × 2。

【需要手动配置吗？】
  不需要。默认 5MB 分片、4 路并发、3 次重试，对绝大多数场景够用。
  只有以下情况才需要改环境变量：

  · 服务器磁盘紧张 → 减小 CHUNK_SIZE_BYTES（如 2MB）减少暂存
  · 单文件特别大（>10GB）→ 增大 CHUNK_SIZE_BYTES（如 10MB）减少请求数
  · 想换暂存目录（如挂了独立磁盘）→ 改 CHUNK_UPLOAD_DIR

【秒传是什么？怎么用？】
  上传前前端先算文件的 SHA-256，发给服务器比对：
  · 命中：服务器已有相同文件，直接复制一份到你目录，秒级完成，不再上传
  · 未命中：正常分片上传
  秒传只对"用户私密文件"生效（同用户范围内）。
  公开/私密/隐藏文件因要走审核流程，不支持秒传。

【上传失败怎么办？】
  1. 看日志：sudo journalctl -u file-download -f
  2. 常见原因：
     · 磁盘满 → df -h 检查
     · 单片 3 次都失败 → 网络不稳定，让用户稍后重试（已传分片不会丢）
     · 合并时 SHA-256 不匹配 → 分片损坏，重新上传即可
     · 配额超限 → 用户私密空间超 10GB，上传通道被锁死，需管理员解锁

【管理员解锁用户上传通道】
  用户超 10GB 配额后上传通道会被锁死。解锁方式：
  1. 先用 root 或 admin 账号登录，10 秒内 7 击 Logo 进管理员面板
  2. 点"用户列表"
  3. 找到带"已锁"标签的用户，点行末"解锁"按钮
  4. 确认
