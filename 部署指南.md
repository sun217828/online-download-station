================================================================
        一：需求
================================================================

1. 一台安装了 Ubuntu 22.04 +的服务器（本地服务器或公司服务器均可）
2. 服务器有公网 IP（如果要外网访问）或内网 IP（仅内网使用）
3. 服务器上有 sudo / root 权限
4. 服务器上行带宽越大越好（决定下载速度）

【重要提醒】以下所有软件均需安装，别漏！

================================================================
第三部分：网络访问配置（已有域名 / 公司内网 二选一）
================================================================

本部分不再使用公网穿透（Tailscale Funnel 等），改为两种常规方案，
按你的实际网络环境二选一即可：

  方案 A：使用已有域名 + Nginx 反向代理（推荐，支持 HTTPS）
          → 同事访问：https://download.你的域名.com
          → 适合公司有自有域名、有公网服务器或已做内网穿透到公网的场景

  方案 B：公司内网直连（最简单，零额外组件）
          → 同事访问：http://服务器内网IP:8080
          → 适合纯内网办公环境，服务器和同事在同一局域网

先查服务器内网 IP（两种方案都要用）：
  hostname -I
  # 输出第一个就是内网 IP，比如 192.168.1.100，记下来


---------------A：使用已有域名 + Nginx 反向代理（推荐）

【适用场景】
你已有一个域名（如 download.yourcompany.com），并能修改其 DNS 解析。
服务器可以是公司有公网 IP 的服务器，也可以是纯内网服务器（通过公司公网入口反代）。

---

A-1：配置域名 DNS 解析

登录你的域名服务商后台：
  1. 添加一条 A 记录：
     主机记录：download（或你想要的子域名前缀）
     记录类型：A
     记录值：你的服务器公网 IP 或公司出口公网 IP
     TTL：默认 10 分钟即可
  2. 保存，等待解析生效（通常 1-10 分钟）
  3. 验证：在任意电脑执行
     ping download.yourcompany.com
     能解析到你的 IP 就 OK

【如果服务器在纯内网】
  需要让公司公网入口（路由器/防火墙）把 80/443 端口转发到内网服务器，
  或在公司已有的反向代理（Nginx/网关）上加一条转发规则指向内网服务器 8080。

---

A-2：给服务器设置固定内网 IP（重要！）

  方法一：路由器/ DHCP 里绑定（推荐）
    在公司路由器或 DHCP 服务器里，把服务器 MAC 绑定到固定 IP

  方法二：Ubuntu 系统里设静态 IP
    桌面右上角 → 网络 → 有线设置 → IPv4 → 改成手动
    地址：192.168.1.100（与现状一致）
    子网掩码：255.255.255.0
    网关：192.168.1.1
    DNS：223.5.5.5 或公司 DNS

---

A-3：安装 Nginx

  sudo apt install -y nginx

---

A-4：配置 Nginx 反向代理

  sudo nano /etc/nginx/sites-available/file-download

粘贴以下内容（按需修改 server_name）：

  server {
      listen 80;
      server_name download.yourcompany.com;   # ← 改成你的域名

      # 大文件上传不缓存，支持分片上传
      client_max_body_size 0;
      proxy_request_buffering off;
      proxy_read_timeout 3600s;
      proxy_send_timeout 3600s;

      location / {
          proxy_pass http://127.0.0.1:8080;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
          # 分片上传要支持长连接
          proxy_http_version 1.1;
      }
  }

启用配置并重载：
  sudo ln -sf /etc/nginx/sites-available/file-download /etc/nginx/sites-enabled/
  sudo rm -f /etc/nginx/sites-enabled/default
  sudo nginx -t
  sudo systemctl reload nginx

---

A-5：申请 HTTPS 证书（Let's Encrypt 免费证书，强烈推荐）

  sudo apt install -y certbot python3-certbot-nginx
  sudo certbot --nginx -d download.yourcompany.com
  # 按提示输入邮箱、同意条款，选择自动把 HTTP 跳转 HTTPS
  # certbot 会自动改好 Nginx 配置并设置自动续期

验证：浏览器打开 https://download.yourcompany.com 应该能看到页面。
证书每 90 天自动续期，无需手动操作。

---

A-6：防火墙放行

  sudo ufw allow 80/tcp
  sudo ufw allow 443/tcp
  sudo ufw allow 8080/tcp   # 内网直连调试用，外网可不开
  sudo ufw reload

若服务器前有公司防火墙/网关，还要在对应设备上放行 80/443 入站。

---

A-7：把网址发给同事

  https://download.yourcompany.com
  告诉同事用浏览器打开即可，无需安装任何软件。


------------------B：公司内网直连（最简单）

【适用场景】
服务器和所有同事在同一公司局域网内，不需要外网访问。
无需域名、无需 Nginx、无需证书，开箱即用。

---

B-1：给服务器设置固定内网 IP（重要！不然重启会变）

参考 A-2，把服务器 IP 固定为 192.168.1.100（示例）。

---

B-2：Ubuntu 防火墙放行 8080

  sudo ufw allow 8080/tcp
  sudo ufw reload
  sudo ufw status
  # 应看到 8080/tcp ALLOW

---

B-3：启动服务

  cd /opt/file-download-server
  node server.js
  # 或已配置 systemd 则：sudo systemctl start file-download

---

B-4：验证

  1. 在同事电脑浏览器打开：http://192.168.1.100:8080
     （把 192.168.1.100 换成你服务器实际 IP）
  2. 能看到页面、能点下载 → 成功！

---

B-5：把网址发给同事

  http://192.168.1.100:8080
  同事用浏览器打开即可。

【可选】在内网 DNS 服务器加一条解析：
  download.intranet → 192.168.1.100
  之后同事就能用 http://download.intranet:8080 访问，更好记。


================================================================
第四部分：配置开机自启（使用 systemd，推荐方案）
================================================================

-------- 步骤 1：创建 systemd 服务文件 --------
sudo nano /etc/systemd/system/file-download.service


-------- 步骤 2：把以下内容粘贴进去（注意路径与用户名一致）--------

# ======= 从下一行开始复制 =======
[Unit]
Description=Private File Download Server v3.1.2
After=network.target

[Service]
Type=simple
User=你的用户名          # <--- 改成你的 Ubuntu 用户名，比如 ubuntu 或 root
WorkingDirectory=/opt/file-download-server
ExecStart=/usr/bin/node /opt/file-download-server/server.js
Restart=always
RestartSec=5

# ====== 环境变量配置区（按需修改）======

# 基础配置
Environment=PORT=8080
Environment=HOST=0.0.0.0
Environment=FILES_DIR=/opt/file-download-server/files

# 审核后台口令（可选）。不设置时服务首次启动会自动生成一个随机口令并打印在启动日志里。
# 若同时配置了 ADMIN_USERS（见下），管理员登录后可免口令进入后台，这一项可以不设。
Environment=ADMIN_PASSWORD=请改成你自己的强口令

# 管理员用户名（逗号分隔，可留空）。
# 服务启动时会把这里列出的【已注册用户】提升为管理员，这是产生第一位管理员的推荐方式。
# 用法：先在网页上正常注册一个账号（例如 myadmin），再把它填到这里并重启服务。
Environment=ADMIN_USERS=myadmin

# 是否开放注册（true/false，默认 true）。设为 false 后只能由管理员手动创建/提升账号。
Environment=ALLOW_REGISTER=true

# 反向代理信任（可选）。部署在 Nginx / Caddy 等反代后面时设为 true，
# 否则 req.ip 会拿到代理内网 IP，导致限速、匿名上传归属判断不准。
# Environment=TRUST_PROXY=true

# 联系管理员邮箱（设置页"通用"标签会展示给用户，方便他们有问题时找你）
Environment=ADMIN_EMAIL=你的邮箱@example.com

# 每用户私密空间配额（字节，默认 10GB = 10737418240）
Environment=USER_QUOTA_BYTES=10737418240

# ====== 邮件停机通知（可选，不配也能用，只是不能发邮件）======
# 用自己的邮箱做发件服务器，给所有填了邮箱的用户群发通知
# 以 QQ 邮箱为例：
# Environment=SMTP_HOST=smtp.qq.com
# Environment=SMTP_PORT=465
# Environment=SMTP_SECURE=true
# Environment=SMTP_USER=你的QQ邮箱@qq.com
# Environment=SMTP_PASS=QQ邮箱授权码（不是登录密码！）
# Environment=SMTP_FROM=你的QQ邮箱@qq.com

# ====== 分片上传（第 4 期新增，一般不用动，保持默认即可）======
# 分片暂存目录（上传中的文件碎片存这里，合并完会自动清理）
# Environment=CHUNK_UPLOAD_DIR=/opt/file-download-server/chunks
# 默认分片大小（字节，默认 5MB=5242880，范围 64KB~10MB）
# 5MB 适合大多数场景：弱网重试成本低，并发数够用
# Environment=CHUNK_SIZE_BYTES=5242880

[Install]
WantedBy=multi-user.target
# ======= 复制到上一行为止 =======

# 保存退出 nano：按 Ctrl+O，回车，再按 Ctrl+X


-------- 步骤 3：加载服务并启动 --------
# 重新加载 systemd 配置
sudo systemctl daemon-reload

# 设置开机自启
sudo systemctl enable file-download

# 启动服务
sudo systemctl start file-download

# 查看运行状态（看到绿色的 active (running) 就成功了）
sudo systemctl status file-download

# 其他常用命令
# sudo systemctl stop file-download       # 停止
# sudo systemctl restart file-download    # 重启（修改 server.js 或环境变量后执行）
# sudo systemctl disable file-download    # 取消开机自启
# sudo journalctl -u file-download -f     # 实时查看日志


================================================================
第五部分：放行防火墙端口
================================================================

Ubuntu 22.04 默认可能开启了 ufw 防火墙，需要放行 8080 端口。

-------- 方案 A：使用 ufw（Ubuntu 默认防火墙）--------
# 查看防火墙状态
sudo ufw status

# 如果是 active（已开启），放行 8080 端口
sudo ufw allow 8080/tcp
sudo ufw reload

# 再次查看确认规则已加入
sudo ufw status numbered


-------- 方案 B：如果你用 iptables --------
sudo iptables -I INPUT -p tcp --dport 8080 -j ACCEPT
sudo netfilter-persistent save


-------- 方案 C：公司有硬件防火墙/网关设备 --------
除了上述系统防火墙，公司网络若部署了独立防火墙/网关：
1. 登录防火墙/网关管理后台
2. 添加入站规则：
   - 协议类型：TCP
   - 端口范围：8080
   - 授权对象：0.0.0.0/0（允许所有 IP，或仅允许公司公网 IP / 内网网段）
3. 保存，约 1 分钟后生效

================================================================
第七部分：创建管理员账号（重要！）
================================================================

系统【不会】自动创建任何账号，也没有默认用户名/密码。
第一次部署后，请按下面的步骤产生你的第一个管理员：

-------- 方式 A（推荐）：注册后提升 --------
1. 浏览器打开网站，在 设置（齿轮） → 用户 → 去注册，注册一个账号，
   例如用户名 myadmin，密码自己设一个强密码（建议 ≥ 8 位，大小写+数字混合）。
2. 编辑 systemd 服务文件，加入（或修改）这一行：
     Environment=ADMIN_USERS=myadmin
3. 重载并重启服务：
     sudo systemctl daemon-reload && sudo systemctl restart file-download
4. 启动日志会出现：
     [管理员] 已将以下用户提升为管理员：myadmin
5. 之后用 myadmin 登录网站，即拥有管理员权限。

-------- 方式 B：直接改数据库 --------
进入项目目录执行（把 myadmin 换成你的用户名）：
  node -e "const d=require('./db');console.log('updated',d.setUserAdminByName('myadmin',true))"
然后重启服务即可。

【关于管理员口令 ADMIN_PASSWORD】
- 管理员身份有两条路进入后台：
    a) 已登录的管理员账号 —— 免口令（推荐）
    b) 输入 ADMIN_PASSWORD 口令 —— 兼容方式，适合没有账号时临时进后台
- 如果你没有手动设置 ADMIN_PASSWORD 环境变量，服务启动时会自动生成
  一个随机口令并打印在启动日志（形如「管理密码 : 1a2b3c4d5e6f」），
  把它记下来即可。想固定口令就在 systemd 里设置 ADMIN_PASSWORD。
- 无论用哪种方式，后台登录都做了频率限制：连续失败多次会临时锁定该来源 IP。

【安全提醒】
- 不要使用 admin / admin123 / 123456 / root123 这类弱口令组合。
- 生产环境务必设置 TRUST_PROXY=true 并在反代层启用 HTTPS，
  这样会话 Cookie 才会带上 Secure 属性。


================================================================
第八部分：管理员面板怎么用
================================================================

【如何进入管理员面板】

v3.1.2 的管理员入口是隐藏的，需要按特定方式触发：

1. 用浏览器打开网站首页
2. 在 10 秒内，连续点击页面左上角的网站图标（蓝色圆角方块）7 次
3. 权限判定（满足其一即可）：
   - 当前登录账号是管理员（ADMIN_USERS 里列过 / 数据库 is_admin=1）→ 直接进入，无需口令
   - 输入 Environment=ADMIN_PASSWORD 里设置的口令 → 进入
   - 两者都没有 → 口令框提示错误，无法进入
4. 口令通过请求头提交，不会出现在浏览器地址栏 / 历史记录 / Referer 里。

【管理员面板能做的事】

1. 待审核列表
   - 用户上传的文件会先到这里等管理员审核
   - 可以通过（公开到下载站）或拒绝（删除）
   - 也可以改为私密文件（仅管理员可见）

2. 公告管理
   - 发布/编辑/删除首页右上角信箱里的公告
   - 公告会显示未读小红点提醒用户

3. 用户列表
   - 查看所有注册用户
   - 显示用户名、邮箱（如有）、空间使用进度条、注册时间
   - 用户超 10GB 配额会自动锁死上传通道
   - 管理员可手动解锁某用户的上传通道

4. 文件列表
   - 查看所有私密文件

5. 停机通知（需配置 SMTP 邮件）
   - 群发邮件给所有填了邮箱的用户

【什么时候需要配】

【前提条件】

1. 你有一个可用的邮箱（QQ 邮箱、163 邮箱、企业邮箱等）

2. 如果显示绿色"✓ 邮件服务就绪"，说明配置成功

  Environment=SMTP_HOST=smtp.163.com
  Environment=SMTP_PORT=465
  Environment=SMTP_SECURE=true

【注意】

- 授权码不是邮箱登录密码，是邮箱设置页单独生成的

第十一部分：可选优化（按需选择）
================================================================

【可选 1】修改端口号
编辑 systemd 服务文件里的 Environment=PORT=新端口
然后：
  sudo systemctl daemon-reload
  sudo systemctl restart file-download
同时防火墙也要放行新端口：
  sudo ufw allow 新端口/tcp

【可选 2】改用 80 端口（HTTP 默认端口，访问时无需加端口号）
# 1. 修改服务端口为 80
# 2. 1024 以下端口需要特殊权限，两种方式：
#    方式 A：允许 node 绑定低端口
#    sudo setcap 'cap_net_bind_service=+ep' /usr/bin/node
#    方式 B：用 nginx 反代（见下）

【可选 3】使用 Nginx 反向代理 + 自定义域名 + HTTPS
如果有域名想通过 https://download.你的域名.com 访问：
1. 安装 nginx：sudo apt install nginx -y
2. 配置文件：sudo nano /etc/nginx/sites-available/file-download
   配置内容（示例）：
   server {
       listen 80;
       server_name download.你的域名.com;
       client_max_body_size 0;  # 不限制上传大小
       location / {
           proxy_pass http://127.0.0.1:8080;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_request_buffering off;  # 大文件上传不缓存
       }
   }
3. 启用配置：
   sudo ln -s /etc/nginx/sites-available/file-download /etc/nginx/sites-enabled/
   sudo nginx -t
   sudo systemctl reload nginx
4. HTTPS 证书用 Let's Encrypt 免费签发即可

【可选 4】限制访问 IP（只允许公司办公室网络访问）
使用 ufw 只允许指定 IP 访问 8080：
sudo ufw delete allow 8080/tcp
sudo ufw allow from 公司公网IP to any port 8080 proto tcp

第十二部分：常见问题排查
================================================================

Q1：浏览器打不开页面？
A：依次检查：
   1. 服务是否运行：sudo systemctl status file-download
   2. 端口是否监听：ss -tlnp | grep 8080
   3. 防火墙是否放行：sudo ufw status
   4. 公司防火墙/网关是否放行了 8080
   5. 服务器 IP 是否能 ping 通

Q2：页面显示「暂无文件」？
A：检查 files 目录下是否有文件：
   ls -lh /opt/file-download-server/files
   注意：隐藏文件（. 开头的）不会显示

Q3：下载速度很慢？
A：本程序是直链下载无限速，速度瓶颈通常是：
   1. 服务器上行带宽（找服务器运营商）
   2. 下载者的下行带宽
   3. 网络路由拥堵
   程序本身不做任何限速

Q4：文件名乱码？
A：Chrome / Edge / Firefox 新版都已支持中文文件名，
   如果遇到个别老浏览器乱码是浏览器问题，不影响下载的文件本身。

Q5：下载到一半断了，续传不生效？
A：只有主流浏览器（Chrome / Edge / Firefox）支持断点续传，
   另外不要删除浏览器里的下载记录，点「继续」才能续传。

Q6：更新了 files 目录里的文件，网页没刷新？
A：点击网页右上角的 ↻ 刷新按钮即可，或按 F5 刷新页面。
   切回浏览器标签页时也会自动刷新。

Q7：npm install 报错 better-sqlite3 编译失败？
A：确认已安装编译工具：
   sudo apt install -y build-essential python3
   然后删除 node_modules 重装：
   rm -rf node_modules
   npm install

Q8：npm install 报错 EACCES 权限问题？
A：执行：
   sudo chown -R $(id -u):$(id -g) ~/.npm
   然后重新 npm install

Q9：用户注册不了/登录不了？
A：检查数据库目录是否可写：
   ls -la /opt/file-download-server/data/
   应该看到 app.db 文件，且当前用户有写权限。
   如果没有，停掉服务，删除 data 目录后重启：
   sudo systemctl stop file-download
   rm -rf /opt/file-download-server/data
   sudo systemctl start file-download

Q10：邮件停机通知发不出？
A：检查：
   1. systemd 服务文件里 SMTP_* 环境变量是否填了
   2. 改完后是否执行了 daemon-reload + restart
   3. 进入管理员面板"停机通知"看状态提示
   4. 看 journalctl 日志：
      sudo journalctl -u file-download -f
      然后发一封测试邮件，看具体报错

Q11：用户上传后没出现在待审核列表？
A：检查 pending 目录：
   ls -lh /opt/file-download-server/pending/
   如果有文件，刷新管理员面板即可
   如果没文件，可能是上传失败，让用户重新上传

Q12：用户私密空间满了传不上去？
A：用户超 10GB 配额后上传通道会自动锁死。
   管理员可在"用户列表"里手动解锁该用户：
   管理员面板 → 用户列表 → 对应用户行 → 点"解锁"
   解锁后用户可继续上传，但建议用户先删除部分旧文件

================================================================
第十五部分：分片上传相关说明（第 4 期新增）
================================================================

【什么是分片上传？为什么用它？】
  旧版上传是一次性把整个文件塞给服务器，超过 100MB 就容易超时失败。
  第 4 期改成"分片上传"：
    前端把大文件切成 5MB 一片，4 路并发上传，单片失败自动重试 3 次，
    全部传完后服务器流式合并。中途断网可断点续传，已存在的文件可秒传。

【会占多少额外磁盘？】
  上传期间会在 chunks/ 目录暂存分片，总大小 = 文件大小。
  合并成功后会自动清理。24 小时未完成的会话每小时自动清理一次。
  所以最坏情况磁盘占用 ≈ 同时上传的所有文件总大小 × 2。

【需要手动配置吗？】
  不需要。默认 5MB 分片、4 路并发、3 次重试，对绝大多数场景够用。
  只有以下情况才需要改环境变量：

  · 服务器磁盘紧张 → 减小 CHUNK_SIZE_BYTES（如 2MB）减少暂存
  · 单文件特别大（>10GB）→ 增大 CHUNK_SIZE_BYTES（如 10MB）减少请求数
  · 想换暂存目录（如挂了独立磁盘）→ 改 CHUNK_UPLOAD_DIR

【秒传是什么？怎么用？】
  上传前前端先算文件的 SHA-256，发给服务器比对：
  · 命中：服务器已有相同文件，直接复制一份到你目录，秒级完成，不再上传
  · 未命中：正常分片上传
  秒传只对"用户私密文件"生效（同用户范围内）。
  公开/私密/隐藏文件因要走审核流程，不支持秒传。

【上传失败怎么办？】
  1. 看日志：sudo journalctl -u file-download -f
  2. 常见原因：
     · 磁盘满 → df -h 检查
     · 单片 3 次都失败 → 网络不稳定，让用户稍后重试（已传分片不会丢）
     · 合并时 SHA-256 不匹配 → 分片损坏，重新上传即可
     · 配额超限 → 用户私密空间超 10GB，上传通道被锁死，需管理员解锁

【管理员解锁用户上传通道】
  用户超 10GB 配额后上传通道会被锁死。解锁方式：
  1. 用管理员账号登录（或输入 ADMIN_PASSWORD 口令），10 秒内 7 击 Logo 进管理员面板
  2. 点"用户列表"
  3. 找到带"已锁"标签的用户，点行末"解锁"按钮
  4. 确认

PART 3: NETWORK ACCESS (existing domain / company intranet — choose ONE)
================================================================

This part no longer uses public tunneling (Tailscale Funnel, etc.). Instead, choose one of the
two standard approaches below according to your actual network environment:

  Option A: Existing domain + Nginx reverse proxy (recommended, supports HTTPS)
            -> Colleagues visit: https://download.yourcompany.com
            -> Best when your company owns a domain and has a public-IP server, or already
               tunnels the intranet to the public internet

  Option B: Direct company intranet connection (simplest, zero extra components)
            -> Colleagues visit: http://<lan-ip>:8080
            -> Best for a purely internal office network where server and colleagues share the LAN

First look up the server's LAN IP (needed by both options):
  hostname -I
  # The first address printed is the LAN IP, e.g. 192.168.1.100 — write it down


---------------A: Existing domain + Nginx reverse proxy (recommended)

[When to use this]
You already have a domain (e.g. download.yourcompany.com) and can modify its DNS records.
The server may be a company machine with a public IP, or a purely internal machine that is
reverse-proxied through the company's public gateway.

---

A-1: Configure domain DNS resolution

Log in to your domain registrar's console:
  1. Add an A record:
     Host / name: download (or whichever subdomain prefix you prefer)
     Record type: A
     Value: your server's public IP or your company's egress public IP
     TTL: the 10-minute default is fine
  2. Save and wait for propagation (usually 1-10 minutes)
  3. Verify from any computer:
     ping download.yourcompany.com
     If it resolves to your IP, you are set.

[If the server is on a private network only]
  Ask the company's public gateway (router/firewall) to forward ports 80/443 to the internal
  server, or add a forwarding rule on your existing reverse proxy (Nginx/gateway) that points at
  the internal server's port 8080.

---

A-2: Give the server a fixed LAN IP (important!)

  Method 1: Bind it in the router / DHCP server (recommended)
    On the company router or DHCP server, bind the server's MAC address to a fixed IP

  Method 2: Configure a static IP inside Ubuntu
    Top-right corner -> Network -> Wired Settings -> IPv4 -> switch to Manual
    Address: 192.168.1.100 (keep it identical to the current lease)
    Netmask: 255.255.255.0
    Gateway: 192.168.1.1
    DNS: 223.5.5.5 or your company DNS

---

A-3: Install Nginx

  sudo apt install -y nginx

---

A-4: Configure the Nginx reverse proxy

  sudo nano /etc/nginx/sites-available/file-download

Paste the following (adjust server_name as needed):

  server {
      listen 80;
      server_name download.yourcompany.com;   # <- change this to your domain

      # Do not buffer large uploads; required for chunked upload
      client_max_body_size 0;
      proxy_request_buffering off;
      proxy_read_timeout 3600s;
      proxy_send_timeout 3600s;

      location / {
          proxy_pass http://127.0.0.1:8080;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
          # Chunked upload needs keep-alive
          proxy_http_version 1.1;
      }
  }

Enable the config and reload:
  sudo ln -sf /etc/nginx/sites-available/file-download /etc/nginx/sites-enabled/
  sudo rm -f /etc/nginx/sites-enabled/default
  sudo nginx -t
  sudo systemctl reload nginx

---

A-5: Obtain an HTTPS certificate (free Let's Encrypt certificate — strongly recommended)

  sudo apt install -y certbot python3-certbot-nginx
  sudo certbot --nginx -d download.yourcompany.com
  # Follow the prompts: enter your email, accept the terms, and choose to redirect HTTP to HTTPS
  # certbot rewrites the Nginx config and sets up automatic renewal for you

Verify: opening https://download.yourcompany.com in a browser should show the page.
The certificate renews automatically every 90 days; no manual action required.

---

A-6: Open the firewall

  sudo ufw allow 80/tcp
  sudo ufw allow 443/tcp
  sudo ufw allow 8080/tcp   # for LAN debugging; can stay closed to the internet
  sudo ufw reload

If a company firewall/gateway sits in front of the server, allow inbound 80/443 there as well.

---

A-7: Share the URL with colleagues

  https://download.yourcompany.com
  Just tell colleagues to open it in a browser — no software to install.


------------------B: Direct company intranet connection (simplest)

[When to use this]
The server and all colleagues are on the same company LAN and internet access is not required.
No domain, no Nginx, no certificate — works out of the box.

---

B-1: Give the server a fixed LAN IP (important — otherwise it changes after reboot)

See A-2 and pin the server IP to 192.168.1.100 (example value).

B-2: Open port 8080 in the Ubuntu firewall

B-3: Start the service

B-4: Verify

  1. Open http://192.168.1.100:8080 on a colleague's computer

  2. The page loads and downloads work -> success!

---

B-5: Share the URL with colleagues

  http://192.168.1.100:8080
  Colleagues simply open it in a browser.

[Optional] Add a record on the intranet DNS server:
  download.intranet -> 192.168.1.100

PART 7: CREATE AN ADMINISTRATOR ACCOUNT (important!)
================================================================

The system does NOT create any account automatically, and there is no default username or password.
After the first deployment, follow the steps below to produce your first administrator:

-------- Method A (recommended): register, then promote --------
1. Open the site in a browser, go to Settings (gear) -> User -> Sign up, and register an account,
   e.g. username myadmin, with a strong password of your own (>= 8 characters, mixing upper case,
   lower case and digits).
2. Edit the systemd service file and add (or modify) this line:
     Environment=ADMIN_USERS=myadmin
3. Reload and restart the service:
     sudo systemctl daemon-reload && sudo systemctl restart file-download
4. The startup log will show:
     [管理员] 已将以下用户提升为管理员：myadmin
5. From then on, log in to the site as myadmin and you have administrator privileges.

-------- Method B: modify the database directly --------
Run this from the project directory (replace myadmin with your username):
  node -e "const d=require('./db');console.log('updated',d.setUserAdminByName('myadmin',true))"
Then restart the service.

[About the ADMIN_PASSWORD passphrase]
- There are two ways an administrator can reach the console:
    a) A logged-in administrator account — no passphrase needed (recommended)
    b) Entering the ADMIN_PASSWORD passphrase — the compatibility path, useful for temporary
       access when you have no account yet
- If you did not set the ADMIN_PASSWORD environment variable manually, the server generates a random
  passphrase on startup and prints it in the startup log (of the form "管理密码 : 1a2b3c4d5e6f").
  Write it down. To pin a fixed passphrase, set ADMIN_PASSWORD in systemd.
- Either way, console login is rate-limited: repeated failures temporarily lock that source IP.

[Security notes]
- Never use weak combinations such as admin / admin123 / 123456 / root123.
- In production, always set TRUST_PROXY=true and enable HTTPS at the reverse proxy, so that session
  cookies carry the Secure attribute.

PART 8: HOW TO USE THE ADMIN CONSOLE
================================================================

[How to enter the admin console]

The admin entry point in v3.1.2 is hidden and must be triggered in a specific way:

1. Open the site's home page in a browser
2. Within 10 seconds, click the site logo (the blue rounded square in the top-left corner) 7 times
3. Access is granted if any one of the following holds:
   - The currently logged-in account is an administrator (listed in ADMIN_USERS / is_admin=1 in the
     database) -> enter directly, no passphrase needed
   - You enter the passphrase set in Environment=ADMIN_PASSWORD -> enter
   - Neither of the above -> the passphrase box reports an error and entry is denied
4. The passphrase is submitted via a request header, so it never appears in the browser address bar,
   the history, or the Referer header.

[What the admin console can do]

1. Pending review list
   - User uploads arrive here first and wait for administrator review
   - Approve (publish to the download site) or reject (delete)
   - Or convert to a private file (visible to administrators only)

2. Announcement management
   - Publish / edit / delete announcements shown in the mailbox panel at the top-right of the home page
   - Unread announcements show a red dot badge to alert users

3. User list
   - View all registered users
   - Shows username, email (if provided), a storage-usage progress bar, and registration time
   - Users who exceed the 10GB quota have their upload channel locked automatically
   - Administrators can manually unlock a given user's upload channel

4. File list
   - View all private files

5. Outage notification (requires SMTP configuration)
   - Broadcast email to every user who provided an email address
   - Used to announce server maintenance, new releases, etc.

6. Sign out
   - Leave administrator mode

PART 12: TROUBLESHOOTING
================================================================

Q1: The browser cannot open the page?
A: Check in order:
   1. Is the service running: sudo systemctl status file-download
   2. Is the port listening: ss -tlnp | grep 8080
   3. Is the firewall open: sudo ufw status
   4. Has the company firewall/gateway allowed 8080
   5. Can the server IP be pinged

Q2: The page shows "No files"?
A: Check whether the files directory contains anything:
   ls -lh /opt/file-download-server/files
   Note: hidden files (starting with a dot) are not displayed

Q3: Downloads are very slow?
A: This program serves direct links with no speed limit; the bottleneck is usually:
   1. The server's uplink bandwidth (talk to your server provider)
   2. The downloader's downlink bandwidth
   3. Network route congestion
   The program itself applies no rate limiting whatsoever

Q4: Filenames appear garbled?
A: Current versions of Chrome / Edge / Firefox all support non-ASCII filenames.
   Garbling in an occasional legacy browser is a browser problem and does not affect the
   downloaded file itself.

Q5: A download broke halfway and resuming doesn't work?
A: Only mainstream browsers (Chrome / Edge / Firefox) support resumable downloads.
   Also, do not delete the download entry in the browser — you must click "Resume" to continue.

Q6: I updated files in the files directory but the page didn't refresh?
A: Click the refresh button at the top-right of the page, or press F5 to reload.
   Switching back to the browser tab also refreshes automatically.

Q7: npm install fails compiling better-sqlite3?
A: Make sure the build tools are installed:
   sudo apt install -y build-essential python3
   Then remove node_modules and reinstall:
   rm -rf node_modules
   npm install

Q8: npm install reports an EACCES permission error?
A: Run:
   sudo chown -R $(id -u):$(id -g) ~/.npm
   Then run npm install again

Q9: Users cannot register or log in?
A: Check whether the database directory is writable:
   ls -la /opt/file-download-server/data/
   You should see app.db and the current user should have write permission.
   If not, stop the service, delete the data directory, and start it again:
   sudo systemctl stop file-download
   rm -rf /opt/file-download-server/data
   sudo systemctl start file-download

Q10: Outage notification emails won't send?
A: Check:
   1. Whether the SMTP_* environment variables are set in the systemd service file
   2. Whether you ran daemon-reload + restart after editing
   3. The status shown under "Outage notification" in the admin console
   4. The journalctl logs:
      sudo journalctl -u file-download -f
      then send a test email and read the exact error

Q11: A user upload never appears in the pending list?
A: Check the pending directory:
   ls -lh /opt/file-download-server/pending/
   If files are present, just refresh the admin console
   If it is empty, the upload probably failed — ask the user to upload again

Q12: A user's private space is full and uploads fail?
A: Once a user exceeds the 10GB quota, their upload channel is locked automatically.
   An administrator can unlock that user manually in the user list:
   Admin console -> User list -> the corresponding user row -> click "Unlock"
   After unlocking, the user can upload again, but it is advisable to delete some old files first

PART 15: NOTES ON CHUNKED UPLOAD (added in phase 4)
================================================================

[What is chunked upload and why use it?]
  The old uploader pushed the entire file to the server in one request, which tended to time out
  above 100MB. Phase 4 replaced it with "chunked upload":
    The frontend slices large files into 5MB chunks, uploads 4 in parallel, automatically retries a
    failed chunk up to 3 times, and the server merges them by streaming once all chunks have arrived.
    An interrupted connection can be resumed, and files that already exist can be "instantly uploaded".

[How much extra disk does it use?]
  Chunks are staged in the chunks/ directory during upload, totalling the size of the file.
  They are cleaned up automatically after a successful merge. Sessions still unfinished after 24
  hours are cleaned up once an hour.
  So the worst case is roughly (total size of all concurrently uploading files) x 2.

[Do I need to configure anything manually?]
  No. The defaults — 5MB chunks, 4-way concurrency, 3 retries — are sufficient for the vast
  majority of scenarios. Only change the environment variables in these cases:

  · Tight server disk space -> lower CHUNK_SIZE_BYTES (e.g. 2MB) to reduce staging usage
  · Particularly large single files (>10GB) -> raise CHUNK_SIZE_BYTES (e.g. 10MB) to reduce request count
  · Want a different staging directory (e.g. a dedicated disk) -> change CHUNK_UPLOAD_DIR

[What is instant upload and how do I use it?]
  Before uploading, the frontend computes the file's SHA-256 and sends it to the server for comparison:
  · Hit: the server already has an identical file, so it copies one into your directory in a fraction
    of a second — nothing is uploaded
  · Miss: fall back to normal chunked upload
  Instant upload applies only to "private user files" (within the same user's scope).
  Public / admin-only / hidden files go through the review flow and do not support instant upload.

[What if an upload fails?]
  1. Check the logs: sudo journalctl -u file-download -f
  2. Common causes:
     · Disk full -> check with df -h
     · A chunk failed all 3 retries -> unstable network; ask the user to retry later (already-uploaded
       chunks are not lost)
     · SHA-256 mismatch during merge -> a corrupted chunk; simply re-upload
     · Quota exceeded -> the user's private space is over 10GB and the upload channel is locked;
       an administrator must unlock it

[Administrator: unlock a user's upload channel]
  Once a user exceeds the 10GB quota, their upload channel is locked. To unlock:
  1. Log in with an administrator account (or enter the ADMIN_PASSWORD passphrase) and click the logo
     7 times within 10 seconds to open the admin console
  2. Click "User list"
  3. Find the user tagged "Locked" and click the "Unlock" button at the end of the row
  4. Confirm
